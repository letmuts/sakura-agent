## 数据结构
本项目采用带源码/数据运行，源码/数据/二进制相耦合的架构
```
主文档规定不同类数据或各业务数据存到哪里以及通用的约定,各类数据的数据结构(头文件/文件名格式/约束等)由对应目录下的readme.md约定,数据流矢/业务机制由项目架构文档或程序文档约定.

data 程序数据文件
  userdata.toml 存储用户的基本信息,api key和对应的"标签"(采用标签管理环境)
  agent.toml 存储agent的基本信息模板(后期迁移到db)
  agentsession 存储事件对话
  programlog 日志存储(待实现)



```

## 版本约定
项目主文档和项目分发的子目录文档需有版本标记,与当前主程序版本一致

非项目分发的项目程序/子文档或插件文档,大版本要与当前版本一致

`0.0.1`

- 首位是大版本号,只在架构更新/主要数据结构更新/恶性bug修复/数据不通过破坏性迁移无法迁移时发生变动时才变化.当然,大版本号变动不代表一定会面临破坏式迁移.session,配置文件,数据库等数据结构的版本约定,各组件的适配版本均由第一位决定,同版本号的项目内容必须保证互相兼容.
- 第二位是迭代版本号,功能更新,数据结构小变等.
- 第三位是修复性更新.不改变主要目录排布和数据结构的迭代也可以只变小版本号.
